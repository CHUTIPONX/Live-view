Pancake Live Sales Monitor v1.8.0 — Vercel Setup
================================================

RECOMMENDED: ADD / DELETE PANCAKE ACCOUNTS FROM THE WEB APP
----------------------------------------------------------
One-time setup in Vercel:

1) Vercel Project -> Storage -> create/connect a PRIVATE Blob store to this project.
2) Vercel Project -> Settings -> Environment Variables:

APP_USER=Owner
APP_PASSWORD=<your password>
APP_SECRET=<long random secret, 32+ chars>
PLSM_CONFIG_STORE=blob

3) Redeploy ONCE.
4) Open /settings in Pancake Live.
5) Press + Add API, paste a Pancake POS API key, Test & Load Stores, then Save Settings.
6) From now on accounts can be added/deleted from /settings. They are shared across devices
   because the encrypted account configuration lives in Vercel Private Blob.

The app encrypts the Blob payload again with APP_SECRET before storage.
Never put a Pancake API key in public client-side JavaScript.

BOOTSTRAP EXISTING VERCEL ENV ACCOUNTS
--------------------------------------
If you already have PANCAKE_POS_API_KEY_1, _2, _3, etc., keep them during the first deploy.
With PLSM_CONFIG_STORE=blob and an empty Blob, /settings shows them as bootstrap accounts.
Press Save Settings once to copy them into the encrypted shared Blob config.
After verifying it works, you may remove the old PANCAKE_POS_API_KEY_* / PANCAKE_LABEL_* / PANCAKE_SHOP_IDS_* bootstrap variables from Vercel.
APP_USER / APP_PASSWORD / APP_SECRET / PLSM_CONFIG_STORE must remain.

ENV-ONLY MODE (NO BLOB)
-----------------------
The app no longer has a 3-account ceiling. You can continue:

PANCAKE_POS_API_KEY_1=...
PANCAKE_LABEL_1=Account 1
PANCAKE_SHOP_IDS_1=ALL
PANCAKE_POS_API_KEY_2=...
PANCAKE_LABEL_2=Account 2
PANCAKE_SHOP_IDS_2=ALL
PANCAKE_POS_API_KEY_3=...
PANCAKE_POS_API_KEY_4=...
PANCAKE_POS_API_KEY_5=...
...etc.

Named suffixes also work, e.g. PANCAKE_POS_API_KEY_THAILAND.
Or use PANCAKE_CONNECTIONS_JSON with any number of entries.
Environment-only configuration is read-only in the app and requires redeploy after Vercel env changes.

STORE SELECTION
---------------
PANCAKE_SHOP_IDS_N=ALL        -> automatic shop discovery
PANCAKE_SHOP_IDS_N=123,456    -> fixed selected Shop IDs

Duplicate Shop IDs across accounts are counted ONCE. If the same shop exists under multiple
credentials, extra credentials are kept as fallbacks for permission/API failures.

SALES SOURCE OF TRUTH
---------------------
Endpoint: /shops/{SHOP_ID}/analytics/sale
split_by[]=User.id
Sales: summary.price / 100
Orders: summary.order_count
Products: summary.product_count

success:true + data:[] + summary:{} means that shop has zero matching sales for the period.
Timeout / permission / malformed response does NOT become zero; the dashboard holds the previous
complete verified total instead.

Authenticated diagnostics: /api/diagnostics


FACEBOOK PAGE DISCOVERY (SEPARATE FROM POS SHOP COUNT)
------------------------------------------------------
The POS /shops endpoint returns POS Shop IDs. It is NOT the same thing as the Facebook Page list.
If you want Settings to show the actual Facebook Page count, add the Pancake User Access Token(s)
used by the old page-discovery project:

PANCAKE_USER_ACCESS_TOKEN=...
PANCAKE_USER_LABEL=Main Facebook Account
PANCAKE_USER_ACCESS_TOKEN_2=...
PANCAKE_USER_LABEL_2=Second Facebook Account
PANCAKE_USER_ACCESS_TOKEN_3=...
PANCAKE_USER_LABEL_3=Third Facebook Account

Or use PANCAKE_USER_TOKENS_JSON. Redeploy after changing Vercel Environment Variables.
Then open Settings -> FACEBOOK PAGE DISCOVERY -> Load FB Pages. The app calls /api/v1/pages
server-side, filters unusable entries, and de-duplicates by Facebook Page ID. User Access Tokens are
never returned to the browser.

A POS API account that exposes only Shop IDs already seen by another POS API account correctly adds
+0 unique POS Shops. This does not mean the API key failed.

SALES METRIC AUDIT
------------------
The main dashboard still uses Pancake Employee Statistic summary.price / 100 as the authoritative
complete-snapshot metric. Verified order cards prefer total_price_after_sub_discount when Pancake
returns it. Settings -> SALES METRIC AUDIT shows the real discount/coupon/voucher/net-like fields
from sample Employee Statistic responses. Do not subtract discounts twice unless the live payload
proves summary.price is a pre-discount metric for your account/report configuration.
